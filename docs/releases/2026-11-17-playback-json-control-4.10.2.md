# 4.10.2 公司 NVR JSON 倍速控制修正

## 已定位的问题

用户测试4.10.1返回 `phase=failed`、`requestedRate=4`、`verifiedRate=1`、`protocol=unsupported`、`commandSequence=null`、`ack=none`、`observedRate=null`、`failure=protocol`。当前代码在收到非0.1的version字段后标记unsupported，随后setSpeed在发送前拒绝该请求。此次失败未进入实际视频速率验证，不能据此判断公司服务或NVR拒绝了倍速指令。

公司研发查阅SDK后确认控制约定为JSON：`{"sequence":0,"cmd":"speed","rate":4}`，sequence递增、rate1恢复正常；本地提供的原始NVRPlayer-SDK也只发送该JSON。此前新增的version驱动二进制切换与未知版本拒绝偏离了这一约定，是本次已证实的客户端阻断原因。

## 修复

- 移除version推断控制协议、未知版本拒绝和36字节二进制倍速报文，统一使用公司SDK的JSON指令及递增sequence。
- 版本元数据不取消正在进行的倍速验证，不覆盖请求序号。
- 保留6秒超时、实际已绘制媒体PTS速率校验、失败重连正常速度和脱敏诊断，不以ACK成功或滑块加速替代真实倍速验证。
- 录像暂停仍停止网络与解码、保留实际位置并在续播时重签；不扩大到上游pause/resume适配。直播没有新增控制。

## 验证与发布

- 测试先行：对现有实现新增/修订公司JSON契约回归，11项失败复现版本拦截或二进制错误分支；移除分支后播放器98项测试通过。
- 发布前完整前端25文件/261项测试、生产构建、脚本语法及diff检查通过；构建仅既有大chunk提示。
- 完整合成媒体浏览器26项通过，含0.2/0.1元数据各桌面/手机JSON契约、四档倍率、媒体/滑块同步、恢复1倍、30秒暂停续播及失败回退；另有既有音频4项浏览器场景通过。没有将合成服务的执行结果作为真实代理/NVR倍速通过。
- 新增4组JSON协议回归实测合成画面倍率3.89–4.00，恢复正常0.98–1.00，滑块同步；服务端实际拒收二进制，避免模拟服务器兼容错误协议掩盖问题。样本版本号为测试输入，不代表真实会话的version值已获知。
- subagent独立只读审查未发现本次阻塞问题；已补新播放会话sequence归零断言。本机Go不在PATH，本轮无Go代码变更，现有Wharf Docker构建包含Go测试与构建。
- 仅发布GitLab `codex/containerize-single-image` / Wharf752，同步GitHub功能分支备份。无数据库、运行配置或流水线改动，不修改正式main。
- 测试验收需确认4.10.2后观察4倍速画面内时间和滑块同步，恢复1倍连续、暂停续播不跳过暂停时间；随后检查2/8/16倍。若仍失败保留新的JSON诊断，不能宣称真实倍速已通过。
- 回滚可选测试前一镜像 `4b8e21c`（4.10.1诊断版）；该版本存在已知协议阻断，仅用于恢复版本，不视为功能恢复。无DDL或数据回滚。
