# 4.10.0 录像回放控制

状态：用户已授权发布测试环境；测试候选已从 GitLab 测试基线提取，验证通过，正在执行备份和推送。尚未取得测试构建或部署成功证据，未发布正式环境。

## 范围

- 原二壮 NVR 录像回放增加快进 10 秒与 2/4/8/16 倍速，直播和数字孪生直播不增加这些按钮。
- 正常速度点击倍速打开底部选择面板；倍速中再点恢复正常，再点重新选择。倍速静音，恢复正常还原用户声音意图。
- 滑块使用成功绘制的视频帧 PTS；媒体停顿时不靠墙钟制造进度。
- 暂停停止网络/解码，保留画面、位置和倍率；继续从保存位置重新签发会话。签发时间取整到秒，定位误差上限还受 NVR 关键帧与服务端取流行为影响。
- 快进、拖动、切换模式和迟到会话响应有隔离；同一次滑块操作只提交一次定位。
- 恢复、快进及拖动在用户手势中准备下一会话的音频；同一秒定位等空操作立即回收未使用实例，音频准备失败统一静音图标、用户状态和实际音量。
- 倍速期间声音按钮禁用并标记“倍速播放静音”，恢复正常速度后恢复原声音意图；若期间音频恢复失败则保持静音，需用户重新开启。

## 实现边界

- 倍速 JSON 命令及 version 0.1 二进制报文来自本地官方 WebSDK 的静态资料；成功 ACK 不视为倍速已生效，需媒体 PTS 在多个窗口按目标速率推进。
- 失败、无进度或超时会显示失败并从最后录像位置重连正常速度，避免只改按钮数字。
- 本地可控媒体源仅验证客户端状态、协议发送、计时和页面交互，不代表真实工控机、WebSocket 代理和 NVR 已通过所有倍率。
- 真实测试环境仍须逐档观察画面 OSD、暂停续播首帧、结束边界和声音恢复。若上游不支持某档，需确认失败回退；不应伪称该档支持。
- 不涉及数据库、部署配置或旧 FLV 回放链路。

## 测试环境验收

1. 录像分别选择 2/4/8/16 倍，确认滑块和画面时间同步加速；无声音是预期。
2. 倍速中点击恢复正常，录像时间连续且按正常速度推进；声音恢复到之前的开关状态。
3. 任一倍率暂停至少 30 秒，画面和滑块停止；继续从暂停处按原倍率播放，不跨过暂停期间。
4. 播放和暂停状态分别快进 10 秒、拖动进度；接近小时段末尾不越界，不重复签流。
5. 手机与桌面检查底部面板、取消、横屏、全屏；直播与数字孪生直播保持原控件。

## 本地复验

1. 在 `frontend` 运行 `npm run dev -- --port 5193`。
2. 安装可用 Playwright 后，通过 `PLAYWRIGHT_MODULE` 指向其模块目录。在仓库根目录运行 `node scripts/playback-controls-preview.mjs`，默认5194预览入口。
3. 在 `frontend` 运行 `node src/playback-controls.browser.mjs`（会自行启动临时合成服务）；可用 `TEST_FILTER` 选择场景。原有声音回归为 `node src/monitor-audio.browser.mjs`。
4. 合成服务拒绝未知 API，浏览器回归阻止外部 HTTP/WebSocket，不使用真实账号、机构或摄像头数据。
