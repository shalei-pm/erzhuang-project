# 4.10.3 回放倍速观测与恢复控制

## 真实反馈与根因

用户在测试环境4.10.2选择4倍后观察到画面短暂加速，随后回到正常速度。诊断为JSON、sequence=0、ACK accepted、observedRate=0.167、failure=timeout。该反馈证明指令已发出且收到成功状态，不证明转封装时间戳等于录像拍摄时间。

代码有两个确定问题：六秒内严格验证不通过便拒绝Promise，上层因此重签正常速度；倍速验证既被并入通用loading，又禁用倍速按钮，用户无法主动恢复。单独解除按钮禁用也不够：旧verifiedRate仍为1，新目标1会被effect提前跳过，SDK又拒绝pending期间的第二个命令。

本轮发现既有转封装WASM的DETAIL_FRAME_INFO还包含nYear/nMonth/nDay/nHour/nMinute/nSecond/nMilliSecond。现有实现只读取nTimeStamp，缺少对录像时间与封装时间的区分。本轮没有获得用户真实流的帧元数据采样，因此不将0.167的具体时间戳成因写成已确认事实。

## 修改

- 继续使用公司JSON速度指令及递增sequence。正常速度rate=1可以替代未完成的加速请求，清除旧计时器；旧序号响应和React旧effect不会触发错误回退。
- 抢占后上游若不回sequence，无法区分新旧状态，立即请求一个普通速度的新会话，不信任迟到的无序号ACK，也不等待第二个六秒超时；这一兼容降级只重签一次，不展示倍速失败通知。
- 分别跟踪请求倍率、已发送命令和实测速率。按钮立即显示请求倍率，验证期间可恢复1倍、暂停、截图；连接中和倍速验证不再混成同一个loading。定位与快进仍在验证期间禁用。
- 解码帧携带其对应的录像时间元数据，优先用有效录像日历时间更新进度、暂停落点及速率观测。时间按帧绑定，避免解码延迟读取到后续帧时间；秒精度相同时间戳仍允许绘制画面。不把倍率乘在滑块上伪造进度。
- 没有有效录像日历时间的会话降级使用container时钟。ACK已接受且画面持续输出，但该时钟不能确认倍率时，结束等待、保留播放，诊断为unconfirmed；保留原verifiedRate，不伪称已经实测成功。不会仅因六秒内无法观测就自动退回1倍。
- 显式拒绝、发送失败、断连、无画面及可靠录像时间连续证明倍率不符时，仍走错误恢复。正常1倍获实测确认，或正常1倍指令获明确接受时，按原用户静音偏好恢复声音。
- 脱敏诊断新增timeSource=recorded/container，只含状态、倍率和序号等白名单字段，不含具体录像日期、摄像头、签流URL、token或原始报文。
- 独立审查发现并补测解码积压超过256帧丢画面、低帧率误当倍率错误、监控flush时间冒充新画面及无序号回复关联四项边界。帧元数据改为输出后清理、倍率错误与样本质量分开、只由成功绘制刷新最近呈现时间，无序号恢复按上述降级重签。
- 新增React effect交互测试，显式声明jsdom开发依赖并以npm ci重新安装验证；不依赖子代理临时安装所改变的本机node_modules。

## 测试环境验收

1. 确认页面4.10.3，播放一段画面内带时钟的录像，选择4倍，观察超过十秒，不能再无故退回普通速度。
2. 选择4倍后立即点倍率按钮，及播放数秒后点倍率按钮，均应发rate=1，原位置连续播放，不受旧六秒计时器干扰。
3. 查看画面内录像时钟与滑块，检查2/4/8/16倍与恢复1倍；有日历元数据时，诊断timeSource应为recorded。
4. 倍速暂停，等待至少十秒，再续播；必须从暂停画面对应位置继续，不能跳过等待的时间。
5. 先开启声音，再加速、恢复1倍，确认按原偏好恢复声音；静音用户保持静音。直播控件不变。
6. 若仍出现unconfirmed，复制诊断并标明画面内时钟是否真实加速。此状态不等于拒绝，也不等于实测速率已经通过。
