## 手机 Safari 直播、录像无声

原有 H5 监控在 NVR 模式下使用 `NVRLabPlayer`。直播 RTP 的 PCMA 音频和录像 WASM 输出的音频最终都进入同一个 Web Audio 输出方法。

已用回归测试复现的代码缺陷：

- 开启声音只恢复 `suspended`，不恢复 Safari 的 `interrupted`；中断上下文会被当作开启成功。
- 中断或挂起时仍按停止推进的音频时钟累加调度，恢复后可能积压旧音频。
- UI 初始为静音，但 SDK 默认音量为 100；点击画面可触发文档级手势监听创建有声上下文。
- 音频开启失败会设置视频错误状态，导致视频控制也被禁用。

修复候选：显式开启声音时申请可选的 `audioSession.type=playback`，在同一次手势内创建或恢复上下文；确认实际进入 running 状态后才切换声音按钮。音频中断或静音时不排队；恢复时按当前音频时钟调度。多个播放器共用播放会话，最后一个静音或关闭时归还原来的会话类型。不支持 Audio Session 的浏览器继续使用 Web Audio。

播放器创建时同步设置音量为 0；开启声音失败只显示可重试提示，不改变视频连接状态。切换页面、锁屏等场景后保留手势恢复能力。

验证范围：单元测试模拟 Safari 中断状态；独立无头 Chrome 使用合成 PCMA 信号覆盖直播、录像、390px 手机和 1440px 桌面视口，并通过 Analyser 检查非零音频输出。浏览器页面没有接入公司 API 或真实视频，没有打开可见窗口。

本地验证：前端 Vitest 全量 `23 files / 149 tests` 通过；`npm run build` 通过（保留既有大体积 chunk 提示）；`CGO_ENABLED=0 go test ./...` 与 `go build ./cmd/server` 通过。浏览器回归最终 `4/4` 通过，含控制台无错误、音频非零输出和页面无横向溢出检查。当前会话没有可调用的 Chrome 插件控制工具，使用独立无头浏览器完成，不干扰用户窗口。浏览器回归脚本为 `frontend/src/monitor-audio.browser.mjs`，应针对新启动、未发生源码热更新的本地 Vite 服务运行；它对播放器传输层使用合成夹具，对 Web Audio 输出使用真实浏览器实现。

限制：本机的 Chrome 合成音频验收不能证明 iPhone Safari 真机已恢复可听声音，也不能证明目标摄像头提供了音轨。需要先在测试环境对同一有音频摄像头验收直播、录像、静音/非静音开关、后台返回后的声音。不能在此之前将线上现象标为完全解决。

## 南京 3 家机构仅 1 家可授权

用户截图：10030、10053、10086 在南京资源列表中；权限弹窗南京候选只有 10053。

代码确认：

- 机构列表来自 `tb_crm_admin_tenant`，以有效工控机筛选，城市按 CRM 的 city_id 映射。
- 权限候选来自 `tb_stores`，只要求 external_org_id 非空，城市使用旧表 city 文本。
- 保存权限以 `tb_stores.id` 写 resource_id，以 external_org_id 写 external_key。
- 回显按内部门店 ID 关联；监控访问检查使用 external_key。

DBA 专项已只读复核上述身份约定，确认不能仅把候选查询换成 CRM 机构表，更不能把机构 ID 当作内部门店 ID 提交。否则存在保存失败或数字碰撞后授错门店的风险。未发现 CRM 到旧门店表的通用自动同步入口。

仍待确认：正式库中的 10030、10086 是没有旧表映射，还是城市值/映射值异常。尚未连接正式库，不能把这个判断当作已查证的数据库事实。

只读核对脚本：`db/monitor_scope_nanjing_readonly.sql`。遵循 `docs/decisions.md` 的既有约定，由运维通过批准链路执行，禁止本机直连正式库。脚本包含三个机构的映射、重复映射、既有授权一致性以及同类遗漏规模检查，不读取用户身份明细。

后续处理：

1. 映射存在但城市不同：核对真实城市，只修正确认错误的旧表属性，不新增重复门店。
2. 映射缺失：DBA 按查询结果准备定向补齐旧表的 DML 与验证、回滚步骤；保留现有内部门店 ID，不改 CRM 同步表，不自动授予用户权限。该数据修复会增加旧门店目录记录，需要审批后执行。
3. 若不接受维护旧目录：另行确定候选、保存、回显、鉴权统一使用公司机构身份的完整方案。本轮未擅自改变权限模型。

验收标准：南京三家都可找到；分别保存后重新打开仍勾选相同机构；内部 ID 与外部机构 ID 不串店；原有授权保持一致。当前未实施任何正式库修复，因此该 bug 尚未关闭。
