# 3.4.11 会话失效修复与测试验收

日期：2026-09-07。目标仅为公司测试分支，不发布 GitLab `main`。

## 已确认的策略

- 连续 30 分钟没有受保护业务请求则失效。
- 最长登录 8 小时，不因持续操作而延长。
- 不以鼠标、键盘活动作为续期依据；静态资源和会话状态检查不续期。
- 超时后清理本地身份并进入公司 SSO 联合退出；再次登录必须验证扫码链路。

## 本地复现与修复

1. 普通 API 在本地 Cookie 缺失时原来自动创建会话。新增回归测试先得到 `200/created=1`，现改为 `401/session_login_required`，只有登录回调能创建会话。
2. 原会话只检查 `expires_at`，持续请求可以无限续期。内存和 MySQL 均同时检查 `last_activity_at + 30 分钟`、`created_at + 8 小时`、撤销状态和 `expires_at`，续期不能超过绝对截止。
3. 同一已校验的 SSO JWT 以 SHA-256 指纹记录在既有 `sso_subject` 字段，带 `jwt-sha256:v1:` 版本前缀，不保存原始 JWT。登录时先锁用户行，再用锁定读检查消费记录，已过期或已撤销的记录也不能重复创建会话。有效本地 Cookie 的回调不会新建会话或重置创建时间。
4. 公司测试/正式域名请求不可因 `SSO_ENABLED` 关闭而进入本地开发免认证逻辑；本地开发行为保持不变。
5. 新增 `GET /api/auth/session-status`，独立验证 SSO 和共享会话，只读剩余时间，不经过会刷新活动时间的门禁。`auth/me` 返回剩余空闲及绝对时长。前端到期或从后台恢复时核对状态，失效后停止显示业务页和播放器。其他标签页仍有请求时，按共享会话的真实剩余时间重新计时。
6. 前端认证请求失败不再回退为已登录管理员；桌面和 H5 统一处理空闲、绝对超时和重新认证错误。

## 数据库与回滚

- 无新增表、字段、索引或 DDL，无实例、Secret、Dockerfile 或流水线变更。
- 本次只有正常登录、续期、撤销和审计写入，未执行线上数据操作。
- 指纹消费记录必须保留；不能按 8 小时删除旧会话记录，否则仍有效的 SSO JWT 可能重新获得创建资格。
- 老版本 `sso_subject` 保存普通 subject，无法反推出 JWT 指纹。不会擅自清表或重写存量数据。
- 回滚恢复本次之前的测试应用版本，保留所有会话和审计记录。回滚会重新引入旧版超时缺陷，不代表安全验收通过。

## 验证分层

- 后端新增回归先失败后通过，覆盖缺 Cookie、回调重放、持续活动 8 小时、异常过大的 expires_at、不续期状态查询。
- 完整 Go 测试在允许本机测试端口的环境运行；macOS 旧 Go 工具链使用 `CGO_ENABLED=1` 和 `-ldflags=-linkmode=external`，不修改容器构建配置。
- MySQL SQL 契约和事务故障测试不等于真实 MySQL 集成验收。没有隔离的 `MYSQL_TEST_DSN` 时，集成测试跳过，不使用业务测试库或正式库代替。
- 浏览器插件当前报 `unsupported Codex auth method: apikey`，未取得真实登录页面控制能力。本地无头浏览器的模拟接口验收与真实公司 SSO 验收分别记录，不能相互替代。

## 测试发布后仍须核实

1. 页面及部署记录确认为 `3.4.11`，不要把 push 成功、构建成功或网关 302 当作部署验收。
2. 登录后保持无业务请求超过 30 分钟。状态接口自身不能续期，页面应退出，再访问应要求扫码。
3. 重启浏览器/丢失本地 Cookie 后，不能用已经消费过的同一 SSO JWT 新建会话。
4. SSO 联合退出后的回调是否收到真正重新认证的凭据。**新 JWT 本身不能证明重新扫码**：目前 JWT claims 没有可验证的 `auth_time`，上游若静默签发另一枚 JWT，本地指纹去重无法识别。存量旧 JWT 首次进入新逻辑同样没有历史指纹可比对。
5. 已建立的外部 NVR WSS 连接由前端卸载播放器关闭。本修复不声称外部取流服务已经支持按二壮会话即时撤销独立 WSS 凭据。

在真实网关和存量会话验证完成之前，不将“必须重新扫码”标记为安全合规闭环，不自动发布正式环境。
