# H5 播放器控制控件设计

## 背景

H5 监控试点页已经跑通真实直播链路：

- 公司线上试点门店可在移动端显示实时视频。
- PC 端首帧误报已修复。
- 播放诊断卡在调试阶段继续常驻展示。

现在进入播放器产品化阶段，目标不是做复杂监控平台，而是让单路监控查看具备基础可控性。

## 产品边界

本模块只做：

- 播放 / 暂停。
- 静音 / 开声音。
- 横屏 / 竖屏切换。
- 全屏。
- 截图。
- 直播和回放的播放状态提示。
- 录像回放片段内滑块定位。

本模块不做，也不预留显性入口：

- 刷新播放流。
- 当前画面异常时重新取流。
- 多画面同屏。
- 云台控制。
- 倍速。
- 下载录像。
- 复杂时间轴。

## 交互设计

### 控制条

播放器画面底部增加轻量浮层控制条。

控件顺序：

```text
播放/暂停 | 静音/开声音 | 截图 | 横屏/竖屏 | 全屏
```

行为：

- 控制条默认显示。
- 播放稳定后数秒淡出。
- 点击或触摸画面后重新显示。
- 鼠标悬停在 PC 端播放器上时保持显示。
- 出错或加载中时保持显示，方便用户理解当前状态。

视觉：

- PC 端按钮尺寸克制，贴近当前后台/H5 页风格。
- 移动端按钮触控面积更大，避免误触。
- 使用图标为主，必要时配短文字或 aria-label。
- 不使用复杂播放器皮肤，不遮挡画面主体过久。

### 播放 / 暂停

- 点击暂停后，播放器暂停画面，按钮变为播放。
- 点击播放后，恢复当前播放地址。
- 如果播放器实例返回 Promise，则等待 Promise 完成后更新状态。
- 如果操作失败，展示 toast 和诊断卡事件。

### 静音 / 开声音

- 初始仍保持静音自动播放，以满足浏览器自动播放限制。
- 点击后调用播放器 `openSound()` / `closeSound()`。
- 声音按钮状态来自前端状态和播放器回调。
- 同一详情页会话内保持用户选择；跨页面暂不持久化。

### 横屏 / 竖屏

移动端横屏切换不强依赖系统方向锁定。

推荐第一阶段实现为“横屏查看模式”：

- 点击横屏后，播放器容器进入全屏或近全屏的横向布局。
- 页面控制条随播放器一起进入横向布局。
- 再次点击返回竖屏详情页。

原因：

- 微信、飞书、移动浏览器对 Screen Orientation API 支持不稳定。
- 直接锁系统方向会带来权限、兼容和退出状态问题。

### 全屏

- PC 端优先使用 Fullscreen API。
- 移动端优先复用横屏查看模式；若 Fullscreen API 可用，再进入元素全屏。
- 退出全屏时恢复竖屏页面布局和底部直播/录像 Tab。
- 如果浏览器不支持全屏，按钮置灰或点击后给出轻提示。

### 截图

截图只做本地查看/保存，不上传、不入库。

优先级：

1. 调用 `ezuikit-flv` 实例的 `screenshot()`。
2. 如果播放器方法不可用，再评估 canvas 抓图兜底。

失败处理：

- 如果截图能力不可用，显示“当前浏览器暂不支持截图”。
- 不因为截图失败影响播放。

## 回放滑块

### 目标

在一个录像片段内，用户可以拖动到更具体的起始时间，而不是只能从片段开头播放。

### 交互

回放页选中片段后，在播放器下方展示片段内滑块：

```text
09:14 ───────●──────── 09:38
当前：09:22:30
```

行为：

- 拖动过程中只更新时间预览，不请求接口。
- 松手后，以当前滑块时间作为新的 `startTime`。
- `stopTime` 保持当前片段结束时间。
- 调用现有 `playRange(startTime, endTime, selectedSegment)` 重新获取回放 URL。
- 新 URL 返回后重新初始化播放器。

不采用浏览器原生 seek 作为主方案，因为萤石 FLV 回放在浏览器内的 seek 能力不确定。重新获取回放 URL 更稳。

### 边界

- 滑块不能拖出当前片段范围。
- 片段小于 2 秒时不展示滑块，只展示当前片段时间。
- 请求新回放 URL 时禁用滑块并显示加载状态。
- 如果请求失败，保留原片段选择和错误提示。

## 技术设计

### 组件拆分

新增或调整：

- `H5FlvPlayer`
  - 继续负责播放器实例、播放生命周期、诊断事件。
  - 通过 ref 暴露受控方法。
- `H5PlayerControls`
  - 负责播放器底部浮层控制条。
  - 接收播放状态和操作回调，不直接接触业务 API。
- `PlaybackSegmentSlider`
  - 负责回放片段内时间滑块。
  - 接收当前片段、当前选择时间、加载态、提交回调。

### Player Ref API

`H5FlvPlayer` 对外暴露：

```ts
type H5PlayerHandle = {
  play: () => Promise<void>;
  pause: () => Promise<void>;
  openSound: () => void;
  closeSound: () => void;
  screenshot: () => Promise<void>;
  enterFullscreen: () => Promise<void>;
  exitFullscreen: () => Promise<void>;
};
```

实际实现中，如果底层播放器方法不是 Promise，也统一包装成 Promise，便于外层处理 loading 和错误。

### 播放状态

前端维护统一状态：

```ts
type H5PlaybackUiState = {
  playing: boolean;
  muted: boolean;
  loading: boolean;
  failed: boolean;
  fullscreen: boolean;
  landscape: boolean;
};
```

状态来源：

- 用户点击控件后的乐观状态。
- 播放器事件回调修正。
- 初始化、切换直播/回放、换 URL 时重置。

### 诊断卡规则

调试阶段继续常驻显示播放器下方诊断卡。

当前规则：

- 不折叠。
- 不隐藏。
- 不改成入口。

只有用户明确说“把诊断收起来”之后，才改为：

- 默认隐藏详情。
- 保留“播放诊断”入口。
- 点击后展开完整诊断。

### 释放播放地址

维持现有规则：

- 退出详情页时失效当前播放地址。
- 直播/回放 Tab 切换时失效当前播放地址。
- 回放滑块提交新时间时，旧播放地址应失效或被新 URL 替换后释放。

## 错误处理

- 播放/暂停失败：toast 显示“播放控制失败”，诊断卡保留底层信息。
- 开声音失败：toast 显示“当前浏览器暂无法开启声音”。
- 截图失败：toast 显示“当前浏览器暂不支持截图”。
- 全屏失败：toast 显示“当前浏览器暂不支持全屏”。
- 回放滑块重新取 URL 失败：toast 显示“回放定位失败，请重试”，保留原片段选择。

## 验收标准

### 直播

- PC 端实时视频可播放，控制条不再误盖错误层。
- 移动端实时视频可播放。
- 播放 / 暂停可切换。
- 静音 / 开声音按钮状态正确。
- 横屏 / 竖屏进入退出正常。
- 全屏进入退出正常，或不支持时提示明确。
- 截图成功或失败提示明确。
- 诊断卡仍常驻显示。

### 回放

- 点击录像片段后可播放。
- 片段内滑块显示起止时间和当前预览时间。
- 拖动滑块时不频繁请求接口。
- 松手后从指定时间重新获取回放 URL 并播放。
- 失败时保留原选择并展示错误。

### 回归

- 直播/回放 Tab 切换仍会释放当前播放地址。
- 移动端 `mobile-wasm` 与 PC 端 `desktop-mse` 首帧判断逻辑不互相误伤。
- 后台非 H5 页面不加载播放器 chunk。

## 实施顺序建议

1. 给 `H5FlvPlayer` 增加 ref API 和播放状态回调。
2. 增加 `H5PlayerControls`，先接播放/暂停、声音、全屏/横屏。
3. 增加截图能力。
4. 增加 `PlaybackSegmentSlider`，接入 `playRange`。
5. 做 PC 和移动端视觉验收。
6. 发布公司环境试点验证。
