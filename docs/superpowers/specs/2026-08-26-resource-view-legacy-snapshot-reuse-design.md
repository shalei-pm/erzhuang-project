# 3.0 摄像头列表复用 2.x 最近截图设计

日期：2026-08-26

## 目标

在新的工控机截图接口可用前，让 3.0「门店空间资源查看」的摄像头列表尽量展示 2.x 已有的通道最近截图。实现必须是只读、可回退且不能把截图映射到错误摄像头。

## 已确认规则

1. 不以业务 NVR ID、业务 NVR 序列号或旧录像机 `device_code` 做映射。三者不存在可验证的一致性。
2. 只处理机构 ID 一致且旧系统中恰有一台有效录像机的门店。
3. 在该门店中，以业务摄像头解析出的 `channel_no` 匹配这台旧录像机下唯一的旧视频通道。
4. 取该旧通道按 `created_at desc, id desc` 排序的最新 `tb_channel_snapshots.thumbnail_path`。
5. 所有不确定情形均不展示旧图，保留现有灰色占位。

这里的“单录像机”指旧 2.x `tb_video_recorders` 中、该门店下有效的录像机数量为一。业务库中的 NVR 数量不参与此判定。

## 数据流

```text
3.0 tenant_id
  -> tb_stores.external_org_id
  -> 单个 tb_video_recorders
  -> tb_video_channels.channel_no
  -> 最新 tb_channel_snapshots.thumbnail_path
  -> 受控预览 URL
  -> 3.0 摄像头列表对应 channel_no 的缩略图
```

后端在资源查看详情聚合时完成这一只读关联。`Camera` 增加可选预览字段；前端仅在该字段存在时渲染图片，否则渲染既有占位。页面不直接持有 OSS key 或签名地址。

## 权限与安全

- 只有现有 `CanViewMonitor` 对该门店为真的用户可获得预览 URL。
- 普通查看用户仍可查看资源列表和绑定状态，但没有监控范围时不获得缩略图。
- 使用应用现有受控图片访问方式，不向前端暴露原始对象路径。
- 不写入 `tb_crm_*`、`tb_stores`、录像机、通道、截图或新增映射表；不复制 OSS 文件；不调用萤石和工控机抓图接口。

## 不命中与错误处理

| 情形 | 页面结果 |
| --- | --- |
| 旧门店不存在 | 灰色占位 |
| 旧录像机数量不是 1 | 灰色占位 |
| 通道号缺失或找到多条旧通道 | 灰色占位 |
| 旧通道没有截图 | 灰色占位 |
| 用户无监控范围 | 灰色占位 |
| 图片加载失败 | 前端退回灰色占位 |

不命中是预期兼容状态，不显示错误通知，不影响门店详情其余数据。

## 验收与测试

后端测试覆盖：

1. 单旧录像机、唯一同通道、存在截图，返回预览字段。
2. 单旧录像机、通道无截图，返回空预览字段。
3. 多旧录像机门店，拒绝按通道号匹配。
4. 无旧门店或旧通道不唯一，返回空预览字段。
5. 用户无该门店监控范围，返回空预览字段。

前端测试覆盖有图、无图和图片加载失败三种状态。发布前统计测试库中单旧录像机门店数、可命中通道数与实际展示数；随后在 Chrome 测试环境实际验收至少一条命中和一条多录像机占位样本。

## 非目标

- 不补全多录像机门店的映射。
- 不修改当前 H5 Monitor 或 NVR 实验页。
- 不实现“刷新截图”。
- 不将本方案作为未来工控机截图接口的替代品。
