# 普通查看用户查看监控门店范围权限设计

日期：2026-07-07

## 背景

当前后台已有全局角色：管理员、编辑运维、普通查看。普通查看用户可以浏览后台普通页面，但不具备写入能力。业务希望进一步限制普通查看用户的监控访问范围：不同负责人只能看到自己负责门店的监控入口和 H5 Monitor 门店切换范围。

本需求只控制“查看监控”能力，不改变普通后台页面的浏览权限，也不把业务负责人范围和设备配置状态混在一起。

静态原型：

- `work/prototypes/viewer-store-scope-demo.html`
- 已确认优先采用 D 版：城市筛选 + checkbox 门店列表。

## 目标

- 管理员在用户管理中给普通查看用户配置可查看监控的门店范围。
- 普通查看用户登录后：
  - 可以浏览普通后台页面和门店资料。
  - 只能在授权门店看到“查看监控”入口。
  - H5 Monitor 门店切换只显示授权门店。
  - 直接访问未授权门店 H5 Monitor URL/API 时，后端返回 403。
- 管理员和编辑运维不受该门店范围限制，默认全量。

## 非目标

- 不限制普通查看用户浏览普通门店详情、列表、设计图资料等非监控页面。
- 不给普通查看用户任何写权限，包括新增、编辑、删除、扫描、识别、确认。
- 不按录像机、通道或设备可用性做授权筛选。
- 第一版不做岗位模板、负责人模板、批量粘贴机构 ID 或城市级持久化 scope。
- 第一版不把 OpenClaw 只读接口纳入同一实现；OpenClaw 另走只读能力设计。

## 权限口径

受限角色：

- `viewer` / 普通查看。

不受限角色：

- `admin` / 管理员。
- `editor` / 编辑运维。

授权粒度：

- 门店级别。
- 候选门店为所有有 `external_org_id` 的门店。
- 不按是否已有录像机、有效通道、已确认区域或 H5 Monitor 当前是否可用来过滤候选范围。

空范围：

- 允许保存。
- 用户仍可登录并浏览普通后台页面。
- 用户不能看到任何门店的“查看监控”入口，也不能进入任何门店 H5 Monitor。

## 数据模型

新增用户资源范围表，第一版只使用门店监控范围，但字段为后续通用 scope 预留。

建议表名：

- `tb_user_resource_scopes`

字段：

- `id`：自增主键。
- `user_id`：关联 `tb_users.id`。
- `resource_type`：资源类型，第一版固定 `store`。
- `resource_id`：资源内部 ID，第一版为 `tb_stores.id`。
- `external_key`：外部业务 key，第一版为 `tb_stores.external_org_id`。
- `scope`：权限范围，第一版固定 `monitor:view`。
- `created_at`。
- `updated_at`。

约束建议：

- 唯一约束：`user_id, resource_type, resource_id, scope`。
- 查询索引：
  - `user_id, resource_type, scope`
  - `resource_type, external_key, scope`

写入策略：

- 保存用户时，如果角色为 `viewer`，同步替换该用户的 `store + monitor:view` scope 集合。
- 保存用户时，如果角色为 `admin` 或 `editor`，不删除已有 scope；只是当前不生效。切回 `viewer` 后恢复原选择。
- 删除用户或禁用用户时，访问仍按现有用户 enabled 状态先拦截；scope 可保留，便于恢复。

## 后端接口

用户管理列表：

- 在用户列表响应中补充普通查看用户的 `monitor_store_scope_count`。
- 管理员/编辑运维可返回 `null` 或标记为全量，不要求展开门店列表。

用户详情/编辑：

- 在用户详情响应中补充 `monitor_store_scopes`：
  - `store_id`
  - `city`
  - `name`
  - `external_org_id`

候选门店：

- 新增或复用只读接口返回所有有 `external_org_id` 的门店候选。
- 字段只需要配置 UI 使用：
  - `id`
  - `city`
  - `name`
  - `external_org_id`

保存用户：

- 创建用户和更新用户接口支持提交 `monitor_store_scope_ids`。
- 后端只在当前操作者具备 `user:manage` 时允许保存。
- 后端必须校验提交门店均存在且有 `external_org_id`。

H5 Monitor 强校验：

- `/api/h5/monitor/stores`：
  - `admin/editor` 返回全部可进入 H5 Monitor 的门店。
  - `viewer` 只返回授权门店与当前 H5 Monitor 可用门店的交集。
- `/api/h5/orgs/{externalOrgId}/monitor`：
  - `admin/editor` 沿用现有逻辑。
  - `viewer` 如果未授权该 `externalOrgId`，返回 403。
- H5 Monitor 的直播、回放、播放地址等下游接口：
  - 需要基于通道所属门店继续校验 `viewer` 是否有该门店的 `monitor:view` scope。
  - 不能只依赖前端隐藏入口。

## 前端交互

用户管理添加/编辑弹窗：

- 当角色为 `普通查看` 时，自动展示“查看监控门店范围”区域。
- 当角色为 `管理员` 或 `编辑运维` 时，隐藏或折叠该区域，并展示“默认全量，不受范围限制”的提示。
- 切换角色时保留已选门店集合；切回普通查看后恢复。

门店范围选择采用 D 版：

- 顶部展示城市筛选 tab：`全部`、各城市。
- 不在城市 tab 上显示已选数量，避免认知负担。
- 搜索框支持门店名、城市、`external_org_id`。
- 列表为紧凑 checkbox list：
  - 左侧 checkbox。
  - 中间门店名，单行省略。
  - 右侧机构 ID。
  - 不重复显示城市小字。
- 操作按钮：
  - `全选`：选中当前筛选结果。
  - `清空`：清空全部已选门店。
- 右上角展示总已选数量。
- 在 `全部` tab 下，已勾选门店前置展示；在具体城市 tab 下保持原始门店顺序。

门店详情：

- 普通查看用户仅在授权门店看到“查看监控”入口。
- 未授权门店不显示入口，但普通资料仍可浏览。

H5 Monitor：

- 门店切换列表只展示授权门店。
- 直接进入未授权 URL 时展示无权限状态，对应后端 403。

## 数据流

保存范围：

1. 管理员打开用户编辑弹窗。
2. 前端加载用户基础信息、当前 scope、候选门店列表。
3. 管理员勾选门店并保存。
4. 后端校验 `user:manage`、角色、门店合法性。
5. 后端替换该用户的 `store + monitor:view` scope 集合。
6. 前端刷新用户列表，展示已选数量。

访问监控：

1. 后端通过 APISIX SSO 解析当前用户。
2. 权限层识别角色。
3. `admin/editor` 放行。
4. `viewer` 查询是否存在该用户对目标门店的 `store + monitor:view` scope。
5. 已授权放行；未授权返回 403。

## 错误与边界

- 候选门店为空：展示空列表和说明，但不影响保存用户。
- 普通查看用户空范围：保存成功，监控入口和 H5 门店切换为空。
- 提交不存在门店 ID：后端返回 400。
- 提交无 `external_org_id` 门店：后端返回 400。
- 当前用户 disabled：沿用现有认证授权逻辑拒绝访问。
- 角色从 viewer 切到 editor/admin：scope 保留但不生效。
- 角色从 editor/admin 切回 viewer：已有 scope 重新生效。

## 测试与验收

后端测试：

- 用户 scope 表写入、替换、保留逻辑。
- 保存 viewer 空范围成功。
- 保存 viewer 多门店范围成功。
- 保存 admin/editor 不删除既有 scope。
- viewer 访问授权 H5 门店成功。
- viewer 访问未授权 H5 门店返回 403。
- `/api/h5/monitor/stores` 对 viewer 只返回授权交集。

前端验证：

- 用户管理弹窗角色切换行为。
- 城市筛选、搜索、全选、清空。
- `全部` tab 已选门店前置。
- 门店详情监控入口按授权显示。
- H5 Monitor 门店切换列表按授权显示。
- 403 无权限页面可读、可返回。

线上回归：

- 管理员创建一个普通查看测试用户，默认空范围。
- 给测试用户授权 1 到 2 家门店。
- 使用测试用户登录，验证普通页面可浏览。
- 验证授权门店可进入监控，未授权门店无入口且直链 403。
- 验证编辑运维和管理员仍可全量访问监控。

## 发布与回滚

发布前：

- 执行 Go 编译门禁和前端构建。
- 做本地或预览环境用户管理页面浏览器验收。
- 确认 migration 向前兼容，新增表不影响现有用户。

发布后：

- 等公司 GitLab/K8s 自动发布完成。
- 在已登录浏览器验证 health、用户管理、门店详情、H5 Monitor。

回滚：

- 代码回滚后，新增 `tb_user_resource_scopes` 表可以暂时保留，不影响旧版本运行。
- 回滚期间普通查看用户恢复旧行为，需要由发布说明明确风险。
