# 通道映射 Excel 导出设计

日期：2026-06-17

## 背景

门店通道映射表需要给各门店人员逐店确认。最初讨论过导出到飞书电子表格，但当前飞书应用权限和目标 Wiki 空间授权尚未打通，且线上业务不应被权限审批阻塞。

P0 改为导出 Excel 文件，由浏览器触发下载。飞书表格继续作为 P1：当“四喜”飞书应用具备 Wiki、电子表格、Drive 上传和目标空间权限后，再升级为在线协作表。

## 目标

- 在门店详情页的通道映射 Tab 增加“导出 Excel”能力。
- 每次导出当前门店的一份通道映射确认表。
- 浏览器直接下载 `.xlsx` 文件。
- 表格内包含摄像头最近截图，供门店人员确认通道和业务区域是否对应。
- Excel 修改结果不自动回写系统。

## 非目标

- 不做飞书电子表格创建。
- 不做飞书权限设置。
- 不做 Excel 修改结果导入或自动回收。
- 不导出全量门店。
- 不导出失效、离线或已删除通道。

## 用户入口

入口位于门店详情页 `通道映射` Tab。

按钮文案：

```text
导出 Excel
```

点击后调用后端导出接口。请求成功时浏览器下载文件；请求失败时页面展示错误提示。

## 文件命名

文件名格式：

```text
门店名称-通道映射确认表-YYYYMMDD-HHmm.xlsx
```

示例：

```text
深圳壹方城-通道映射确认表-20260617-1530.xlsx
```

文件名需要清理系统不安全字符，避免影响浏览器下载和不同操作系统打开。

## 导出范围

仅导出当前门店下仍有效的通道记录：

- 导出待确认通道。
- 导出识别失败但仍有效的通道。
- 导出已确认业务区域通道。
- 导出已确认其他区域通道。
- 不导出失效通道。
- 不导出离线通道。
- 不导出用户已删除的通道。

如果当前门店没有可导出的有效通道，后端返回业务错误，前端提示：

```text
当前门店暂无可导出的有效通道
```

## 排序规则

导出行按业务确认顺序排序：

1. 面诊室
2. 治疗室
3. 生美
4. 其他区域

同类型内排序：

1. 业务区域按编号升序。
2. 其他区域按备注文本升序。
3. 录像机编号升序。
4. 通道号升序。

未识别或待填写的有效通道归入“其他区域”之后，按录像机编号和通道号排序。

## 表格列

P0 表格列固定为：

| 列 | 字段 | 说明 |
| --- | --- | --- |
| A | 序号 | 当前导出表内从 1 开始递增 |
| B | 城市 | 门店城市；旧数据缺失时显示“未设置” |
| C | 门店名称 | 当前门店名称 |
| D | 新氧机构ID | 当前门店的新氧机构 ID；缺失时为空 |
| E | 录像机编号 | 录像机设备编码 |
| F | 通道号 | 摄像头通道号 |
| G | 最近截图 | 嵌入图片 |
| H | 业务区域类型 | 面诊室、治疗室、生美、其他区域 |
| I | 编号/备注 | 业务区域显示编号；其他区域显示备注 |

不导出确认状态、最近识别时间、导出时间。

## 图片规则

- `最近截图` 列必须使用通道最近截图的大图源文件，不使用缩略图源。
- Excel 表格中按缩略尺寸展示图片，保持行高和表格可读性。
- 图片按比例缩放，不允许拉伸变形。
- 不增加“大图链接”列。
- 图片作为 Excel 图片对象嵌入。用户在 Excel、WPS 或飞书表格预览中点击图片后，应能选中、放大或查看更清晰版本。
- 不保证所有客户端都有一致的弹窗式大图预览；P0 的最低验收标准是图片源清晰、表内展示不变形，用户可通过放大图片对象或表格查看清晰图。
- 没有截图的通道，图片列显示“无截图”。

## 后端接口

新增接口：

```http
GET /api/store-space/stores/{store_id}/channel-mappings/export.xlsx
```

响应：

- 成功：`200 OK`
- Content-Type：`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- Content-Disposition：`attachment; filename*=UTF-8''<encoded-filename>.xlsx`
- 失败：返回现有 JSON 错误格式。

后端职责：

- 读取门店详情、录像机、通道、截图资产。
- 按导出范围过滤通道。
- 按排序规则生成导出行。
- 从 AssetStore 读取大图截图文件。
- 使用 Excel 库生成 `.xlsx`。
- 设置表头样式、列宽、行高、冻结首行、图片尺寸。

## 前端行为

前端新增 API 方法：

```ts
exportChannelMappingExcel(storeId: number): Promise<void>
```

实现方式：

- 调用后端导出接口。
- 从响应头读取文件名，解析失败时使用默认文件名。
- 使用 Blob 创建临时下载 URL。
- 创建临时 `<a download>` 触发浏览器下载。
- 请求中按钮进入 loading 状态，避免重复点击。
- 请求失败时展示错误提示。

## 数据和架构边界

- 系统仍然是主数据源。
- Excel 是确认快照，不作为主数据源。
- 本期不保存导出历史记录。
- 不要求导出后可回写。
- 图片通过现有 AssetStore 读取，兼容本地文件和 Supabase Storage。

## 错误处理

- 门店不存在：`404`。
- 无有效通道：业务错误，提示“当前门店暂无可导出的有效通道”。
- 截图读取失败：
  - 不阻断整份导出。
  - 对应图片列显示“截图读取失败”。
  - 后端记录日志。
- Excel 生成失败：返回 `500`，前端提示“导出失败，请稍后重试”。

## 验收标准

- 在某个有有效通道的门店详情页点击“导出 Excel”，浏览器下载 `.xlsx` 文件。
- 文件名符合 `门店名称-通道映射确认表-YYYYMMDD-HHmm.xlsx`。
- 失效、离线、已删除通道不出现在 Excel 中。
- 行顺序符合：面诊室、治疗室、生美、其他区域。
- Excel 列为：序号、城市、门店名称、新氧机构ID、录像机编号、通道号、最近截图、业务区域类型、编号/备注。
- 截图列展示图片，图片不变形，图片源使用大图。
- 没有截图的通道显示“无截图”。
- 修改 Excel 后不会自动影响系统数据。

## 后续 P1

飞书表格导出作为 P1：

- 复用“四喜”飞书应用。
- 创建飞书电子表格。
- 放入指定 Wiki 空间。
- 写入通道映射数据和图片。
- 权限允许目标人员编辑。
- 是否回收飞书修改结果另行设计。
