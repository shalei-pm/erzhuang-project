# 工控机监控全量替换设计

状态：用户已确认设计，待实施计划
日期：2026-08-26
范围：二壮项目所有已完成工控机摄像头配置的门店

## 1. 目标

将正常业务中的“查看监控”入口由萤石云 H5 Monitor 全量切换为公司工控机 NVR 取流方案。用户从门店详情或监控导航进入时，看到的是工控机摄像头列表和已在 10001 验收的直播、回放、进度定位、声音、暂停和全屏能力。

本次全量的含义是：新链路成为唯一可见的日常监控入口，不再给用户新旧方案二选一。旧萤石实现保留在代码和数据库中，仅用于版本或运行时回滚，不在新界面暴露。

## 2. 已确认业务规则

### 门店准入

门店仅在存在至少一台符合以下口径的业务摄像头时展示“查看监控”入口：

```text
category = 'camera'
AND provider = 'HikVisionNvrChannel'
AND status = 1
AND deleted_at IS NULL
```

门店没有符合口径的摄像头时：

- 门店详情不展示“查看监控”。
- 监控门店导航不展示该门店。
- 不进入空白页，不自动回退萤石。

摄像头及空间信息只读自已同步到 `db_pm_erzhuang` 的 `tb_crm_*` 表；不新增人工映射维护，不写业务表。

### 权限

- `admin` 和 `editor`：可浏览及观看全部已配置工控机的门店和摄像头。
- `viewer`：仅可浏览及观看自身 `monitor:view` 门店授权范围内、且已配置工控机的门店。
- 所有接口在服务端再次校验角色与门店范围，前端隐藏入口不作为安全边界。

### 播放

- 直播：由二壮后端按摄像头业务 ID 实时请求公司鉴权服务，返回短期 WSS 会话。
- 回放：固定日期和一小时段；拖动进度条只变更本次会话 `start_time`，始终保留原小时窗口作为滑块比例基准。
- 继续使用仓库内固定版本的 NVRPlayer、WASM 和 worker；短期 token、完整 WSS URL、长期 Authorization 均不得渲染、缓存或写入日志。

## 3. 推荐方案：替换正常 H5 监控路由

采用新通用 `nvrmonitor` 模块替代现有只限 10001 的 `nvrlab` 实验边界。前端正常路由保持用户已熟悉的地址：

```text
/h5/orgs/{externalOrgId}/monitor
/h5/orgs/{externalOrgId}/monitor/cameras/{cameraId}
```

旧萤石频道深链接 `/h5/orgs/{externalOrgId}/monitor/channels/{channelId}` 的旧频道 ID 与业务摄像头 ID 不可安全互换。新版本访问该地址时统一提示监控地址已更新，并返回该门店的新摄像头列表；不得猜测映射或静默打开错误画面。

后端新增或演进为下列受认证接口：

```text
GET  /api/h5/nvr-monitor/stores
GET  /api/h5/nvr-monitor/orgs/{externalOrgId}/cameras
POST /api/h5/nvr-monitor/orgs/{externalOrgId}/cameras/{cameraId}/stream-session
```

- `stores` 仅返回准入门店，并按权限过滤。
- `cameras` 仅返回所属准入门店的有效业务摄像头，包含空间展示信息和受控的已有缩略图 URL。
- `stream-session` 再次验证门店、摄像头、角色和门店范围后，才调用公司鉴权服务。
- HTTP 响应强制 `Cache-Control: no-store`，错误响应使用稳定中文错误码且不含敏感上游内容。

前端复用已经验收的 NVR 观看页和播放器控制，不再维护单独的实验页信息架构。与现有 H5 Monitor 一致，门店导航按城市分组，摄像头列表支持既有空间类型筛选和返回路径。

## 4. 入口与回滚

新增服务端运行时配置：

```text
MONITOR_PLAYBACK_MODE=nvr | legacy
```

- 测试与正式切换时设为 `nvr`，正常入口、资源查看 API 的 `can_view_monitor` 和 `monitor_url` 都依据 NVR 准入结果计算。
- 紧急回滚时改为 `legacy` 并滚动重启实例，恢复原萤石入口、原数据口径和原播放器，不需要回写数据库。
- 配置模式只在经认证的应用初始化响应中返回为非敏感枚举，绝不经前端环境变量或静态构建写死。
- 旧萤石代码、表和账号配置在本版本保留；稳定运行后另开清理需求，清理前必须完成数据依赖盘点与回滚点确认。

该开关是运行时快速回滚手段；GitLab 上一个稳定 commit 仍是第二层版本回滚点。

## 5. 数据与实现边界

- 不需要新的数据库表、DDL 或业务库写操作。
- 复用 `resourceview` 对 `tb_crm_admin_tenant`、`tb_crm_iot_device`、`tb_crm_iot_area_device_relation`、`tb_crm_consulting_room` 的只读访问。
- `resourceview` 中的监控入口判定从旧录像机/萤石通道改为当前播放模式对应的 NVR 准入结果；普通用户范围继续复用 `CanUserViewMonitorStore`。
- `nvrmonitor` 不读取萤石账号、旧录像机序列号或旧通道 ID 来换取播放地址。旧截图仅作为已授权的缩略图复用来源，缺失时使用默认占位。
- 现有 10001 实验路由在全量版本验证后移除或重定向到正常路由，避免长期存在两套行为不同的播放页面。

## 6. 可观测性与风险

后端只记录脱敏事件：门店 ID、摄像头业务 ID、模式、请求结果类别和耗时。禁止记录 Authorization、token、WSS URL、媒体字节或录像画面。

上线观察指标：

- 具备 NVR 准入门店数与摄像头数。
- 摄像头列表成功率。
- 会话签发成功率、首帧成功率、首帧耗时和重连率。
- 按门店、角色、直播/回放维度聚合的失败类别。

已知风险：NVR 上游尚未定义可由二壮配置的全局并发上限。本期不凭空引入可能误伤业务的并发限制；先观察会话和首帧指标，若出现容量告警，再与接口方确认限额后单独实施服务端限流。

## 7. 验收与发布

### 测试环境

1. 只读统计准入门店及摄像头覆盖，抽取多城市门店验证空间展示、缺缩略图和无准入隐藏入口。
2. 验证管理员、编辑运维均能看到全部准入门店；普通查看只看到自己授权且准入的门店，直接构造越权 URL/API 请求必须失败。
3. 对至少三家不同城市门店验证直播首帧；对有录像样本验证回放、小时选择、中段和末段进度定位。
4. 验证未配置门店在资源查看列表、详情和监控门店导航均不出现入口。
5. 验证旧频道深链接的提示和返回；不允许打开错误摄像头。
6. 验证所有页面、控制台和 API 错误均不泄露凭据或会话地址。
7. 在测试 K8s 设置 `MONITOR_PLAYBACK_MODE=nvr`；切至 `legacy` 复验旧入口可恢复，作为回滚演练。

### 正式环境

1. 先确认线上 `K8S_SECRET_NVR_STREAM_AUTHORIZATION`、同步资源表、`MONITOR_PLAYBACK_MODE` 和回滚 commit 均已就绪。
2. 已验收代码合入 GitLab `main`，等待 Wharf pipeline `771` 构建成功。
3. 在 Wharf 发起部署并完成审批，将线上配置切为 `nvr`。
4. 使用管理员、编辑运维、普通查看三种账号完成线上冒烟；覆盖已配置和未配置门店、直播和回放。
5. 若关键播放或权限问题无法快速恢复，先将模式切回 `legacy` 并滚动重启；必要时回滚至上一个稳定 GitLab commit。

## 8. 非目标

- 本期不删除萤石代码、账号配置或历史数据。
- 本期不新增抓图、录像片段查询、AI 识别、清晰度切换或 NVR 上游并发限流。
- 本期不修改门店、空间、摄像头关系等同步业务数据。
