# 摄像头空间类型与名称展示设计

日期：2026-08-19

## 背景

3.0 详情页当前把摄像头关联空间按完整父子路径拆成“空间层级 1/2/3、床位”四列。业务库中直接关联到 `parent_id=2387` 的空间只是“诊室区域”容器，不应视为有效摄像头绑定。运营核对需要直接看到可用关联的父空间名称和当前空间名称。

## 决策

- 摄像头与空间关联仍以 `tb_crm_iot_area_device_relation.device_id -> area_id` 为唯一来源。
- 对每一条摄像头关系，查 `tb_crm_consulting_room` 的 `area_id`：若该空间的 `parent_id=2387`，忽略该关系。
- 其他存在空间记录的关系为有效绑定：空间类型取该空间父级记录的 `name`，空间名称取该空间记录自身的 `name`。
- 若关联空间自身的 `level=3`，空间类型固定显示为“治疗室”，优先级高于父级名称。
- 父级缺失或 `parent_id=0` 时，保留关联，空间类型显示 `-`；不由前端猜测类型。
- 同一摄像头可以保留多条有效空间关联，在两个字段内按同序逐行显示。
- 直接绑定到诊室区域的摄像头因关系被忽略，视为未绑定；这同样影响门店“已绑定 / 未绑定 / 已确认”统计。
- H5 Monitor、录像机与通道解析、数据库写入路径均不改。

## 示例

设备 `70` 关联空间 `2665` 和 `2667`：

- `2665.parent_id=2387`，忽略。
- `2667.parent_id=2665`，`2665.name=产研中心`，`2667.name=产研中心1-2`。
- 摄像头详情显示：空间类型 `产研中心`，空间名称 `产研中心1-2`。

## 验收

- 详情表列为“录像机编号、通道号、摄像头 ID、最近截图、绑定状态、空间类型、空间名称”。
- 仅有被忽略关系的摄像头显示“未绑定”。
- 有可用关系的摄像头显示父级名称和当前空间名称。
- 门店统计与详情已绑定行数一致。
