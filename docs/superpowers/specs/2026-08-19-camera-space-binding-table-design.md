# 摄像头空间绑定关系详情页设计

日期：2026-08-19

## 目标

将 3.0 门店详情改为摄像头与空间绑定关系核对页。用户按摄像头逐行确认录像机、通道、绑定状态和业务空间路径，不再以空间树、设备树和异常项作为默认工作界面。

## 本版范围

- 顶部展示门店名、机构 ID、摄像头数、已绑定数、未绑定数、最近映射更新时间和查看监控入口。
- 主表一行一台摄像头，列为：录像机编号、通道号、摄像头 ID、最近截图、绑定状态、空间层级 1、空间层级 2、空间层级 3、床位。
- 空间路径由 `spaces.parent_id` 从绑定空间向上回溯。禁止直接依赖业务表 `level` 字段，因为真实数据存在层级值不稳定的情况。
- 摄像头有多条有效绑定时仍只展示一行；每条绑定路径在各空间列中按相同行序展示，避免丢失多对多关系。
- 无有效空间绑定的摄像头显示“未绑定”，空间列统一显示 `-`。
- 最近截图列保留但显示 `-`。当前 3.0 只读接口没有截图 URL，本版不调用旧抓图链路，也不伪造图片。

## 本版不做

- 不做区域筛选，待查看真实三级/床位分布后另行定义。
- 不做重新截图，操作列不渲染，避免无效入口。
- 不修改 H5 Monitor、播放器、业务库、资源查看后端 API 或截图资产。
- 不保留旧详情的空间视角、设备视角、异常项 Tab。

## 展示规则

- 录像机编号优先用 NVR `hardware_id`，没有时回退 NVR 名称，再回退 NVR ID。
- 通道号由已有摄像头 `channel_no` 展示；没有时显示 `-`。
- 绑定状态只表示是否存在有效摄像头-空间关系，不代表设备在线状态或人工确认。
- 父子链最多展示四段：前三段填入空间层级 1/2/3，第四段填入床位。超过四段时将末段合并到床位；少于四段时未占用列显示 `-`。
- 表格按录像机编号、通道号、摄像头 ID 稳定排序。

## 验收

- 详情页只有摄像头绑定关系表，没有旧三 Tab。
- 未绑定摄像头仍会出现，且空间列均为 `-`。
- 真实测试门店可看到绑定路径；页面不因多条绑定或孤儿关系崩溃。
- 1440px 桌面宽度下表格可水平滚动，不压缩或重叠关键列。
- 详情页“查看监控”入口保持现有权限行为。
