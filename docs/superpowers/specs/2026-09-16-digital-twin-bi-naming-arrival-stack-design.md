# 数字孪生 BI 指标口径与到院人次三段堆积设计

日期：2026-09-16

## 目标

统一数字孪生右侧 T+1 BI 的业务称谓、单位和客群图例，并把“到院人次”图改造成数据可核对的路径堆积图。图表不得通过前端差值伪造“前台签到”数据。

## 指标名称与单位

| 当前名称 | 新名称 | 单位 |
| --- | --- | --- |
| 到访人数趋势 | 到院人次 | 人次 |
| 平均在店时长 | 在店时长 | 分钟 |
| 平均等待时长 | 平均等待时长 | 分钟 |
| 升单率趋势 | 升单率 | % |
| 人均核销金额 | 核销客单价 | 元/人次 |
| 人均核销服务点 | 人均服务点数 | 点/人次 |

单位调整同时覆盖图表标题区域、坐标或辅助文案、无障碍描述和 tooltip。到院图 tooltip 示例为 `55 人次`，不能继续显示 `55 人`。

## 客群命名

除到院图外，所有 BI 图例统一为：

```text
全部顾客 / 非面诊 / 面诊
```

替换关系：

- `无需咨询` 改为 `非面诊`。
- `需要面诊`、`需要咨询` 统一改为 `面诊`。
- 数据字段和接口兼容名称可以暂时保留，前端展示文案必须统一。

## 到院人次图

### 完整数据状态

数据服务提供以下四个同日指标时，到院图展示三段堆积柱：

- `visit_all`：全部顾客。
- `visit_front_desk`：前台签到。
- `visit_no_consult`：非面诊。
- `visit_need_consult`：面诊。

实际绘制的三个色块为：

```text
前台签到 / 非面诊 / 面诊
```

图例下方使用弱提示说明：

```text
全部顾客 = 前台签到 + 非面诊 + 面诊
```

`全部顾客` 不再绘制为第四个重复色块。tooltip 同时展示全部顾客总数和三个路径明细，便于核对三段之和。

### 过渡与缺失状态

当前数据接口只确认提供 `visit_all`、`visit_no_consult` 和 `visit_need_consult`，尚无独立的 `visit_front_desk`。

在任意一天缺少 `visit_front_desk`，或三个路径字段没有全部取得时：

- 当天只绘制 `visit_all` 的“全部顾客”单色柱。
- tooltip 展示全部顾客；已有但不完整的路径数据可以作为明细展示为实际值，缺失项显示 `—`，但不能绘制成不完整堆积柱。
- 不使用 `visit_all - visit_no_consult - visit_need_consult` 推算前台签到。
- 不把缺失值改写为 `0`。

当数据服务后续返回完整三类路径字段时，页面无需人工开关，按天自动切换为三段堆积。30 天范围允许完整日与缺失日分别采用三段堆积和总数单柱，不因某一天缺字段而降低整张图的其他日期。

## 数据契约

T+1 后端响应新增可选字段：

```json
{
  "date": "2026-08-25",
  "visit_all": 55,
  "visit_front_desk": 3,
  "visit_no_consult": 34,
  "visit_need_consult": 18
}
```

数据服务原始字段建议同名使用 `visit_front_desk`。如果数据部门最终采用其他字段名，只在 Provider 适配层映射，不把外部字段差异扩散到前端。

所有分类必须由数据部门确认满足以下口径：

- 前台签到、非面诊、面诊三类互斥。
- 三类覆盖全部到院路径。
- 四个指标使用同一“人 + 日期去重”的核销人次口径。
- `visit_all = visit_front_desk + visit_no_consult + visit_need_consult`。

应用只负责展示和轻量一致性诊断，不自行修正业务数据。当完整四项均存在但合计不一致时，仍显示接口原值，并记录不包含用户明细的诊断信息；不得静默篡改任一数值。

## 视觉规则

- 沿用现有数字孪生深绿色 BI 卡片、坐标、tooltip 和图例样式。
- 前台签到使用与现有绿色、橙色有清晰区分的低饱和蓝色。
- 非面诊沿用绿色，面诊沿用橙色，全部顾客单柱沿用现有灰白色。
- 图例只表达实际绘制的系列；总数与分组关系通过弱提示和 tooltip 说明。
- 不增加新的卡片、弹窗或操作入口。

## 验收标准

1. 六张 BI 卡片的新标题、单位和图例文案全部正确，不再出现旧称谓。
2. Tooltip 中到院单位为“人次”，核销客单价为“元/人次”，人均服务点数为“点/人次”。
3. 到院某日四项数据完整时，只绘制前台签到、非面诊、面诊三个堆积色块；三段总和与全部顾客一致。
4. 到院某日缺少前台签到或其他路径字段时，只绘制全部顾客单色柱，不绘制不完整的两段堆积。
5. `0` 是有效业务值，显示为 `0`；未取得数据显示 `—`，两者不能混淆。
6. 不存在前端差值推算前台签到的代码路径。
7. 30 天中不同日期可以按各自数据完整性选择三段堆积或总数单柱。
8. 桌面常用宽度和移动端图例不溢出，tooltip 不遮挡关键内容。
9. 前端单元测试、Go T+1 映射测试、生产构建和独立浏览器图表验收全部通过。

## 发布边界

- 本轮不修改数据库、Secret、Dockerfile、nginx 或流水线配置。
- 先发布 GitLab 测试分支 `codex/containerize-single-image` 验收。
- 数据部门尚未补字段时，也可以先验收名称、单位、图例和单柱回退行为。
- 数据字段上线后再次使用真实日期验证三段合计，不需要重新设计页面。
