# 门店空间资源管理系统 PRD

最后更新：2026-06-11

版本：v0.1 正式草案

## 1. 背景

新氧青春门店当前有两类空间资源信息需要线上化管理：

- 装修设计图：用于确认门店有哪些治疗室、面诊室、生美区域，以及这些区域在图纸中的位置。
- 安防摄像头：每个门店部署海康威视录像机和摄像头，以前通过多维表格维护门店、录像机、摄像头通道号、区域的对应关系，再由 OpenClaw 读取表格并调用萤石云 API 查看对应诊室画面。

现有多维表格存在维护成本高、总部难以判断通道对应区域、存量门店设计图可能后补等问题。

本项目将在当前 `erzhuang-project` 的设计图标记能力上升级为“门店空间资源管理系统”。系统以门店和业务区域为核心主数据，设计图和视频通道都是区域数据的来源与校验方式。

## 2. 目标

第一版上线后，需要支持：

- 创建门店空间资源档案。
- 通过设计图识别和人工标注维护业务区域。
- 通过录像机和萤石云 API 扫描有效通道。
- 通过通道截图和 AI 识别预填区域类型、编号和非业务画面类型。
- 支持人工确认通道与业务区域的映射关系。
- 让设计图和摄像头通道可以互相反推、互相校验。
- 替代多维表格中“门店、录像机、通道号、区域”的核心维护工作。

## 3. 核心原则

- 门店先建档，区域主数据逐步沉淀。
- 区域主数据独立于设计图和摄像头。
- 设计图识别可以生成区域主数据。
- 通道映射确认也可以生成区域主数据。
- 设计图不是创建门店的必填项。
- 录像机不是创建门店的必填项。
- 创建门店时，设计图 PDF 和录像机设备编码至少需要提供一个。
- 摄像头识别到的非业务画面只记录在通道上，不进入业务区域主数据。
- AI 结果只做预填，必须人工确认后才生效。
- 第一版必须可用，真实接入萤石云 API 和 AI 识别，不以纯 mock 作为交付目标。
- 尽可能复用现有设计图标注能力，避免重写已经满意的图纸交互。

## 4. 术语

### 4.1 门店

门店是空间资源管理的主体。

字段含义：

- 门店名称：系统内唯一，必填。
- 新氧机构 ID：新氧内部系统中的机构 ID，选填，不是本系统数据库 ID。
- 设计图：门店装修 PDF，可后补。
- 录像机：海康威视/萤石云下的录像机设备编码，可多台。

### 4.2 业务区域

业务区域是系统需要维护设计图和摄像头映射关系的核心空间资源。

第一版固定三类：

- 治疗室
- 面诊室
- 生美

编号规则：

- 三类业务区域编号均必填。
- 编号只允许数字。
- 编号在同门店、同区域类型下唯一。

唯一匹配口径：

```text
区域类型 + 编号
```

例如：

- 面诊室 2
- 治疗室 2

两者不是同一个区域。

### 4.3 非业务画面类型

摄像头可能识别到非三类业务区域的画面。非业务画面不生成业务区域，也不要求设计图圈选。

第一版枚举：

- 前台
- 走廊
- 通道
- 候诊区
- 大厅
- 门口
- 库房
- 药房
- 机房
- 未知

## 6. 页面结构

### 6.1 门店列表

页面顶部：

- 添加门店按钮。
- 门店名称搜索框。

列表字段：

- 序号
- 门店名称
- 新氧机构 ID
- 设计图状态
- 录像机数量
- 通道数量
- 面诊室数量
- 治疗室数量
- 生美数量
- 更新时间
- 操作

操作：

- 进入详情
- 删除

排序：

- 默认按最近更新时间倒序。

搜索：

- 按门店名称包含关键词搜索。

删除门店二次确认文案：

```text
删除后将清除该门店的设计图、区域、录像机、通道、截图和识别结果，且无法恢复。是否确认删除？
```

删除门店为彻底删除。

### 6.2 添加门店浮层

添加门店使用浮层表单。

字段：

- 门店名称：必填。
- 新氧机构 ID：选填。
- 设计图 PDF：选填。
- 录像机设备编码：选填，默认 1 个输入框，可点击按钮增加，最多 3 个。

保存规则：

- 门店名称必填。
- 设计图 PDF 和录像机设备编码至少填一个。
- 同名门店不允许直接创建。
- 疑似同名需要提示确认。
- 同一门店内录像机设备编码不允许重复。
- 全系统录像机设备编码不允许重复。

错误提示：

```text
请至少上传设计图或填写一个录像机设备编码
```

创建成功后：

- 自动进入门店详情。
- 如果创建时上传了设计图，默认进入设计图标注 Tab。
- 如果创建时只填写录像机，默认进入通道映射 Tab。
- 如果两者都有，默认进入设计图标注 Tab。

### 6.3 门店详情

门店详情第一版只有两个 Tab：

- 设计图标注
- 通道映射

不做独立基础信息 Tab。后续系统会整合到新氧其他项目，基础信息不在本项目内展开。

## 7. 设计图标注 Tab

### 7.1 基本规则

- 门店可以没有设计图。
- 上传设计图后不自动识别。
- 用户手动点击“识别图纸区域”后才开始 AI 识别。
- AI 只识别三类业务区域：治疗室、面诊室、生美。
- AI 识别到前台、走廊、通道等非业务画面时忽略，不进入区域主数据。
- AI 识别失败时，仍允许用户基于已有区域手动画框。
- 用户也可以手动新增业务区域和图纸标注。

### 7.2 匹配和生成区域

图纸识别结果按以下口径匹配已有区域主数据：

```text
区域类型 + 编号
```

匹配上：

- 绑定已有区域。
- 生成或更新该区域的图纸矩形框。

未匹配上：

- 作为新的待确认业务区域候选。
- 用户确认后生成正式区域。
- 用户不确认则忽略。

### 7.3 反向补图纸标注

如果区域主数据中已有某个业务区域，但图纸未识别到它，例如通道映射已确认“治疗室 1”，则设计图 Tab 需要反向提示用户补充图纸标注。

交互规则：

- 系统在图纸可见区域生成一个明显的待确认矩形框。
- 该矩形框不代表真实位置，只是占位。
- 用户点击右侧区域卡片后，可定位到该矩形框。
- 用户拖动/缩放矩形框到正确位置后保存。

待确认矩形框样式建议：

- 虚线边框。
- 浅色填充。
- 标签显示：`治疗室 1 待标注`。

### 7.4 设计图状态

设计图状态：

- 未上传
- 待识别
- 待标注
- 已完成

设计图标注已完成标准：

- 门店已上传设计图。
- 所有业务区域都有图纸矩形框。
- 所有矩形框都已人工确认。

如果业务区域来自通道映射，但图纸还没标注，则设计图状态为待标注。

## 8. 通道映射 Tab

### 8.1 录像机列表

通道映射 Tab 顶部展示录像机列表。

字段：

- 录像机设备编码
- 状态：在线 / 离线
- 有效通道数
- 操作：扫描通道 / 删除录像机

规则：

- 允许新增录像机。
- 单门店最多 3 台录像机。
- 录像机设备编码全系统唯一。
- 删除录像机时，同步删除其通道、截图、识别结果和绑定关系。
- 删除录像机需要二次确认。

录像机状态：

- 在线
- 离线

状态来源：

- 完全以萤石云 API 返回为准。
- 未调试通或无权限时，视为离线。

### 8.2 萤石云账号

系统需要维护多个萤石云账号。

账号字段：

- 账户名
- appKey
- appSecret
- accessToken

填写录像机时，需要选择一个萤石云账户名，再填写录像机设备编码。

安全规则：

- 前端只展示账户名。
- appKey、appSecret、accessToken 只由后端保存和使用。
- 编辑账号时可以重新填写密钥，但不完整回显密钥。
- 密钥不进入 GitHub。

如果扫描时设备不存在或不属于所选账号，提示：

```text
设备不存在或当前萤石云账号无权限
```

并将录像机状态置为离线。

账号使用规则：

- 录像机必须明确选择一个萤石云账号。
- 系统按录像机关联的账号调用萤石云接口。
- 不允许系统在账号缺失时默认使用某个兜底账号。
- 萤石云接口错误需要展示清晰原因，不能只提示“失败”。

### 8.3 扫描通道

扫描通道按单台录像机触发。

按钮：

```text
扫描该录像机
```

扫描规则：

- 只保留有效通道。
- 通道号以萤石返回或业务配置为准，系统不自动加减 1。
- 通道是否可抓图，最终以抓图成功为准。
- 重新扫描时：
  - 仍有效通道保留原确认结果。
  - 新增有效通道加入列表，状态未确认。
  - 不再有效通道标记为失效并隐藏，不立即删除。

### 8.4 通道列表

通道列表按录像机分组展示。

字段：

- 录像机编号
- 通道号
- 最近截图
- 业务区域类型
- 编号
- 确认状态
- 操作

确认状态下：

- 业务区域类型和编号不可编辑。
- 操作显示“编辑”。

未确认状态下：

- 业务区域类型和编号可编辑。
- 操作显示“确认”。

点击“编辑”后：

- 回到未确认状态。
- 用户可修改业务区域类型和编号。

### 8.5 抓图识别

支持：

- 识别本录像机全部通道。
- 单通道重新识别。

不做全门店全部录像机一键识别。

队列规则：

- 同一台录像机内，一个通道一个通道抓图和识别。
- 避免萤石云 API 和 AI 接口并发压力。
- 同一通道短时间内不重复抓图，避免触发萤石限流。
- 页面展示进度，例如：

```text
正在识别 3/12：录像机 xxx 通道 5
```

失败处理：

- 单通道抓图或 AI 识别失败时，最多重试 3 次。
- 3 次仍失败，状态标记为识别失败，并继续下一个通道。
- 识别失败的通道提供重新识别按钮。

### 8.6 截图保存

每个通道保存：

- 最近一次缩略图。
- 最近一次大图。

展示：

- 通道列表直接显示缩略图。
- 点击缩略图打开大图预览。
- 页面展示本系统保存后的图片，不直接依赖萤石云临时图片地址。
- 萤石返回的原始图片地址只作为服务端下载的中间地址，不作为长期业务数据展示。

过期：

- 大图一周后删除文件。
- 保留缩略图和识别结果。
- 大图失效后提示重新抓图。

### 8.7 编号纸提示

识别按钮附近展示提示：

```text
请将白底黑字编号纸放在画面明显位置，例如：治疗室 1 / 面诊室 2 / 生美 3。
```

不做额外判断条件。

### 8.8 通道确认

AI 结果必须人工确认后才生效。

AI 识别到业务区域但没识别到编号：

- 状态为待确认。
- 用户可以重新单通道识别。
- 用户也可以手动填写编号后确认。
- 确认为业务区域时，编号必填。

AI 识别到非业务类型：

- 用户仍需点击确认。
- 确认后状态为已确认-非业务画面。
- 不生成业务区域。
- 不要求编号。

通道确认为业务区域时：

- 如果同门店已有相同“区域类型 + 编号”，自动绑定已有区域。
- 如果没有，确认动作创建正式区域并绑定。

多个通道绑定同一业务区域：

- 允许。
- 提示：

```text
该区域已绑定其他通道，确认后该区域将关联多个摄像头通道。
```

一个通道最多绑定一个业务区域，或者标记为非业务画面。

## 9. 门店状态

### 9.1 通道状态

- 待扫描：录像机在线但还没有扫描通道。
- 待识别：有效通道还没有截图识别。
- 待确认：AI 识别后尚未人工确认。
- 已确认-业务区域：已绑定或生成业务区域。
- 已确认-非业务画面：已确认为非业务画面。
- 识别失败：抓图或 AI 识别 3 次失败。
- 已失效：重新扫描后通道不再有效。

### 9.2 通道映射状态

通道映射已完成标准：

- 所有有效通道都已确认。
- 业务通道已绑定或生成业务区域。
- 非业务通道已确认非业务类型。
- 没有识别失败或待确认通道。

机构列表第一版不展示通道映射状态，只展示录像机数量和有效通道数量。

### 9.3 门店完善状态

门店已完善标准：

- 如果门店有设计图，则设计图标注已完成。
- 如果门店有录像机，则所有录像机都在线，且通道映射已完成。
- 至少有 1 个正式业务区域。

如果多台录像机中有一台离线，门店不能算已完善，显示部分完善或存在异常。

## 10. 区域删除规则

第一版不允许直接删除已绑定通道或图纸标注的业务区域。

删除业务区域前需要先处理：

- 解除通道绑定。
- 删除或取消图纸标注。

避免误删正在被设计图或视频通道引用的主数据。

## 11. 验收标准

### 11.1 添加门店

- 只填门店名称时保存失败。
- 上传设计图或填写录像机设备编码之一即可创建门店。
- 同名门店被拦截。
- 多个录像机输入框最多 3 个。
- 录像机设备编码重复时被拦截。
- 创建成功后自动进入正确 Tab。

### 11.2 设计图标注

- 上传设计图后不自动识别。
- 点击识别后才调用 AI。
- 识别到三类业务区域可匹配或生成区域主数据。
- 已有业务区域未在图纸标注时，图纸上出现待确认占位框。
- 用户可以拖动/缩放占位框并保存。
- 设计图状态随标注完成度变化。

### 11.3 通道映射

- 可为门店新增多台录像机，最多 3 台。
- 单台录像机可扫描有效通道。
- 只显示有效通道，失效通道隐藏但不立即删除。
- 可按单台录像机队列识别全部通道。
- 识别进度可见。
- 单通道失败重试 3 次。
- AI 结果必须人工确认后生效。
- 业务通道确认后生成或绑定业务区域。
- 非业务通道确认后不生成业务区域。
- 多通道绑定同一区域时提示但不阻止。

### 11.4 删除

- 删除门店彻底删除全部关联数据。
- 删除录像机彻底删除该录像机相关通道、截图、识别结果和绑定关系。
- 已被引用的业务区域不能直接删除。

## 12. 待确认事项

- 多萤石云账号密钥加密存储方案。
- AI 通道截图识别的模型 key 和接口形式。
- OpenClaw 后续查询接口入参和返回格式。
